# Morph Lab v12 — Discovery Studio

A procedural monster creator with saved discoveries, seeded variation, and fixed-parent mixing. The existing library has 89 models and 73 part families. All models, textures, and motion are generated by code.

## Open the tool

Open `dist/Morph-Lab.html`. **Create is now the start screen.** Create, Inspect, and Advanced workshop are inside the same HTML file. Do not open the source `index.html` directly from disk; serve source files as described below.

The creator first draws actual model geometry with the offline CPU viewer. It then uses **Three.js r181 and WebGL2** when available. An engine or graphics failure leaves the creator available. The CPU viewer is not the GPU material renderer. The advanced physics Workshop still needs **Rapier compat 0.19.3**, Three.js, and WebGL2.

The supplied HTML is the CDN edition. Create, saved-collection import/export, inspection, and GLB export work offline. The optional GPU view and advanced Workshop need the pinned engine downloads. `npm run build -- --offline` embeds the engines when they are installed.

## Main workflow

1. Select **Randomize monster**, **Vary current**, or **6 variations**.
2. Select **Save discovery** to keep a separate copy. Load it later to make another branch.
3. Use the saved card's **A** or **B** button to set mixer parents. Change the blend, then select **Keep mix** or **Cancel**.

Locks apply during rolls and mixing. The six channels are Body, Head parts, Other parts, Surface, Colors, and Motion. Head parts are attachments; the Body channel controls the body and head dimensions. A head/other-part lock also holds the body and rig to preserve attachment mounts. A body-only roll is disabled while either attachment lock is on.

Saved discoveries remain unchanged when the current creature is edited, varied, or mixed. The collection has a 48-entry limit. Full collections do not silently discard old entries. Export a collection backup before moving the HTML or changing browsers. When storage is unavailable or full, the interface states that the collection is kept in memory only.

A seed is not a complete asset. Use **Export roll / mix recipe** to retain the source snapshots, channel values, locks, seed, and result. Use **Export blueprint** for the editable resulting creature.

## Frame-time correction

The previous Workshop combined a fresh `performance.now()` reading with an animation-frame timestamp. After a mode change, the resulting time step could be negative. `src/core/frame-clock.js` now derives both ends of the interval from animation-frame callbacks. It resets on mode and visibility changes, emits zero on the first callback, and bounds large gaps. The physics validator still rejects invalid caller time; it was not removed.

## Run the source

Use Node.js 20 or later.

```sh
npm install
npm run dev
```

Open `http://localhost:3000/` for Create, `http://localhost:3000/?review=1` for Inspect, or `http://localhost:3000/?workshop=1` for the advanced Workshop. Installed engine files are served locally. The package pins remain `three@0.181.0` and `@dimforge/rapier3d-compat@0.19.3`.

## Build and test

Core, CPU geometry, recipe, collection, and export tests do not require the engines.

```sh
npm test
npm run test:creator
npm run test:examples
npm run build -- --cdn
npm run test:creator-ui
npm run test:all-ui
```

The browser tests require Python Playwright and Chromium. Set `CHROMIUM_PATH` when Chromium is not at `/usr/bin/chromium`. `test:creator-ui` uses the exact combined HTML and real controls. It does not replace Three.js, Rapier, or browser storage with fake APIs.

```sh
npm run doctor
npm run test:coverage-engine
npm run test:engine
npm run build -- --offline
```

The last group needs the installed engines. Use **System checks → Check engines + physics** on the computer that runs the Workshop. A blocked check is not a pass.

## New code

| Module | Responsibility |
|---|---|
| `src/core/frame-clock.js` | Safe callback-time intervals |
| `src/creator/generator.js` | Deterministic rolls, isolated traits, locks, six-candidate batches, and replayable mixes |
| `src/creator/session.js` | Current model, fixed parents, preview transaction, and undo/redo |
| `src/creator/library.js` | Validated local collection, capacity checks, merge, favorites, and backup |
| `src/creator/preview.js` | Actual CPU preview, thumbnails, camera controls, and optional WebGL2 activation |
| `src/creator/webgl-preview.js` | Real Three.js preview without a physics dependency |
| `src/creator/app.js` and `creator.css` | Creator-first interface |
| `scripts/workspace-shell.js` | State transfer inside the single-file release |

The existing Inspector, five-channel advanced mixer, physics habitat, and GLB delivery remain available. The creator adds an independent head-attachment channel on top of the existing mixing system. It does not change the blueprint schema or replace the existing anatomy factories.

## Limits

Mixing blends recipes, not arbitrary mesh topology. Different body graphs and rig families switch between sources. Existing geometry warnings remain. Saved discoveries are local, not cloud accounts. Recent undo/redo is limited to the current creator session; it is not a permanent edit history.

The optional GPU view, advanced Workshop, and direct Windows file launching could not be executed in the authoring environment. Read `verification.json` for actual test results and limits. Do not treat CPU rendering as proof of GPU appearance or physics behavior.
