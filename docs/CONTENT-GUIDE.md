# Morph Lab v4 — Modular content guide

## Scope

This release expands the content registries and their runtime factories. It preserves the two rig families and the five-channel mixer. It does not add a second physics controller, combat system, or AI system.

Engine pins are Three.js r181 (`0.181.0`) and Rapier 3D `0.19.3`. The renderer requests WebGL2. All graphical content is generated by code. The delivered HTML loads the engines from a CDN. The offline build requires installed engines.

Core and editor tests pass. Engine downloads failed in the authoring environment, and its browser did not provide WebGL2. The rendered content and physics still need real-engine release checks. See `test-results/v4-verification.json`.

| `banner` | Pennant, forked, standard | Procedural membrane wave |

The full catalog has 28 families. Each family exposes size, length, twist, bend, phase, flex, symmetry, and three variants. Not every control affects every rigid family. For example, a crystal has no flex animation.

A factory grows along local +Y. The assembler positions and orients the root. The factory must animate children or vertex buffers, not overwrite the root attachment frame. The banner was checked against this rule during source review.

Humanoid blades and staffs default to the right hand. Shields default to the forearm. Shoulder plates default to the upper arm. Other defaults use the body host. Anatomy exposes the socket and local offset. A hand holding a blade or staff gets a minimum procedural finger curl. This is not a prop-specific grasp solver. It does not align both hands to one object.

Equipment is visual. It has no separate collider, inventory slot, damage rule, or drop behavior. Individual equipment parts can also be placed on creatures as ornaments.

## Grouped part kits

Open the **Kits** library. Select **Add kit**. The kit expands into normal genes. The result is selected and remains editable. The operation adds exactly one history entry. Undo removes the whole kit; Redo restores it.

| Kit | Contents | Rig |
| --- | --- | --- |
| Guard | Sword, shield, paired shoulder plates | Humanoid |
| Traveler | Expedition pack, walking staff, pennant | Humanoid |
| Caster | Crystal staff, paired shoulder shards | Humanoid |
| Herald | Standard, tower shield, shoulder plates | Humanoid |
| Wild head | Antlers, ears, muzzle | Either |
| Mineral | Crystal crown, paired body shards | Either |
| Botanical | Fungal cap, leaves, root tendrils | Either |
| Avian | Beak, wings, crest | Either |

Kits append parts. They do not replace an existing loadout. Repeated additions can create overlapping parts. Delete the old parts first to replace a kit.

The operation checks the rig and gene cap before it changes the store. It fails without changing the source when the kit is incompatible or exceeds 32 genes. Each new gene gets a unique ID. Missing named hosts fall back to a valid body node. Humanoid-only kit buttons are disabled on creatures.

A kit is not a new save format. Export its result as a normal blueprint or actor manifest.

## Part materials

Anatomy adds a **Part material** choice:

| Choice | Result |
| --- | --- |
| Factory default (`inherit`) | Keep the factory's normal material mix |
| Skin | Use the body's layered skin material |
| Armor | Use the shared armor response |
| Bone | Use the shared bone response |
| Cloth | Use the shared cloth response and generated bump texture |
| Metal | Use the shared metal response |
| Glow | Use the shared emissive response |

The choice replaces structural surfaces. Eyes, pupils, glints, dark grips, and other protected details keep their assigned material. It does not add independent per-part colors or texture seeds. The material classes use the blueprint's palette.

Material choices serialize with genes. They survive mutation, mixing, duplication through kits, actor generation, and JSON import/export. A part material change rebuilds the part runtime. A surface uniform edit reuses body geometry. Microtexture changes replace the height texture, not the body mesh.

## Surfaces

The eight new pigment patterns are **rosettes, mottled, veins, weave, lattice, woodgrain, circuit, and patches**. There are 18 patterns in total. The four-layer shader uses object-space coordinates. Append new pattern IDs; do not reorder IDs without updating the shader mapping.

The six new microtextures are **weave, brushed, bark, pitted, hex, and leather**. There are ten choices in total. Each is a seeded 128 × 128 RGBA height texture. Height textures affect bump shading, not silhouette or collision.

The eight new material recipes are **linen, leather, iron, bronze, bark, porcelain, biofiber, and circuit**. There are 14 recipes in total. These are combinations of the existing surface fields. They do not select extra renderer types. Color palettes now total 12, including ivory, moss, glacier, iron, amethyst, and rust.

Pattern code and seeded texture buffers were checked at the data level. GPU compilation and rendered pattern quality remain unverified in this environment.

## Motion

The four new locomotion recipes are **backpedal, side step, prowl, and trot**. Creature rigs can use all 12 states. Humanoids support idle, walk, run, creep, backpedal, side step, prowl, and trot. The other four weights remain stored but are inactive on humanoids.

Backpedal reverses the preview stride. Side step uses a lateral stride channel. The habitat controller still rotates toward its movement vector. It is not a combat-strafe controller. No root-motion track is generated.

The three new gait styles are **proud, nimble, and limping**, for seven styles in total. They change posture, arm swing, lift, or side-dependent stride. They do not change actor role data.

The twelve new humanoid actions are **bow, kneel, pray, inspect hand, reach/use, carry, push, work strike, thrust, kick, dodge pose, and roar**. There are 23 actions plus **No action**. The system still has one masked action layer over locomotion, not a general multi-action animation graph.

Kneel, kick, and dodge use the full-body mask by default. The other new actions default to the upper-body mask. An upper-body mask leaves foot IK active. Full-body actions can override the visual legs, but never move or resize the physics collider. Kneel derives its pelvis height from the current front-leg dimensions. Its knee and foot contacts are not guaranteed on arbitrary terrain.

Carry and push are poses; they do not detect or move an object. Work strike uses a gripping pose; it is not a crafting system. Roar opens the jaw; it adds no sound. The banner uses a bounded wave on a vertex grid, not collision-aware cloth. Body intersections are possible.

### Timing markers

Reach/use emits `interact-contact`. Push emits `push-contact`. Work strike emits `work-contact`. Thrust and kick emit `attack-contact`. Dodge emits `dodge-peak`. Roar emits `voice-cue`.

Markers come from normalized action times. Seeking emits no markers. The sampler bounds catch-up work after long frames. A marker does not prove a physics contact. Your game must perform its own target, distance, collision, and damage checks.

## Mixer changes

The five channels remain Body, Parts, Pigment, Surface, and Motion. New content uses those channels. No parallel mixer state is introduced.

Part matching now includes **part type, structural host path, and socket**. Same-type parts attached to different humanoid joints do not merge into one matched gene. Matching is still structural, not semantic matching by weapon purpose or biological function.

Compatible numeric fields interpolate. Part material and variant choices switch at the midpoint. Unmatched parts use the existing presence fade. Channel locks preserve frozen values. Preview always reads source snapshots, not its last result. Apply is one undo step.

Cross-family mixing selects one rig family. It does not morph humanoid bones into a creature skeleton. Unsupported data is retained where valid and reported through compatibility notes.

## Reuse without the editor

These core operations need no Three.js, Rapier, DOM, or local storage:

```js
import {preset} from './src/core/presets.js';
import {applyPartKit} from './src/core/kits.js';
import {defaultMixSettings, mixGenomes} from './src/core/mixer.js';
import {actorManifest, generateActorBatch} from './src/core/actors.js';

const equipped = applyPartKit(preset('wayfarer'), 'guard').genome;
const settings = defaultMixSettings();
settings.topology = 'a';
settings.channels.body = 0.25;
settings.channels.parts = 0.6;

const result = mixGenomes(equipped, preset('grovekeeper'), settings);
const actor = actorManifest(result.genome);
const roster = generateActorBatch(result.genome, {
  count: 6, seed: 4201, variation: 0.3
});
console.log(result.notes, actor, roster);
```

Use the validated import functions for external JSON. They reconstruct allowed fields and reject malformed data. Do not execute imported functions or treat role fields as executable instructions.

### File map

`core/expansion-catalog.js` defines part metadata and the material allowlist. `core/content-pack.js` defines model metadata and kit recipes. `core/expansion-presets.js` builds the model blueprints. `core/kits.js` applies kits atomically. `core/expansion-motion.js` samples the new actions. `creature/expansion-parts.js` supplies the new geometry factories. `core/surfaces.js` generates texture data. `creature/shaders.js` supplies pigment functions.

To add content, extend the relevant registry and its runtime implementation. Update type declarations and tests. A button without a runtime consumer is not a completed part or action.

## Saved files and exports

Blueprint schema is now version 4. Versions 1–3 are accepted and reconstructed as version 4. Missing per-part materials become `inherit`. Older files keep their prior visual material assignments. New states default to zero weight when absent.

The blueprint save slot uses a v4 key and can load prior keys. Mixer recipes remain format version 1; their embedded blueprints upgrade through the common validator. Actor manifests and rosters remain format version 1. They include the complete blueprint and rig compatibility data.

The 65 example files include three new mixer recipes: Grovekeeper × Clockwork, Crownstag × Shardback, and Oracle × Sun manta. Both sources, settings, and results are included. Two kit results and a traveler roster demonstrate other new workflows.

## Release checks

Run the pure core and example tests first. Build the CDN HTML, then run the editor harness. Run real-engine CPU tests after `npm install`. Run shader and full-browser tests on a WebGL2 system.

The delivered checks passed 313 core tests, 145 editor checks, and 65 examples. The new mixer matrix covers 37 × 37 × 3 = 4,107 source-pair/blend cases. Syntax checks are recorded separately in the verification report. No engine or GPU test is counted as passed when a dependency or WebGL2 is missing.

Before a production release, render all new models and all three variants of each new family. Check both rig families. Scrub each new action, then test play, replay, masks, and event timing. Change microtextures repeatedly and inspect resource counts. Check grasp positions, clipping, knees, feet, banner bounds, and mirrored attachments. Enter and exit the habitat. Test save/import and an offline build with network disabled.

This remains a procedural foundation, not a complete NPC game engine. No new AI, navigation, combat, physical clothing, baked glTF export, audio, retargeting, or crowd simulation is included.
